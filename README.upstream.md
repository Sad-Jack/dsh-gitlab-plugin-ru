# dsh-gitlab-plugin

Запросы на слияние, обсуждения проверки кода и сборки GitLab внутри DeepSeek Harness. Подключение — REST API и персональный токен доступа.

Часть **[DeepSeek Harness Plugins](https://github.com/k0ndrateff/dsh-plugins)** автора [@k0ndrateff](https://github.com/k0ndrateff): интеграции Jira, Confluence, Sentry, GitLab и Figma для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), а также проектные проверки на их основе. Пакеты доступны в [индексе каталога](https://k0ndrateff.github.io/dsh-plugins/market.json) и [README коллекции](https://github.com/k0ndrateff/dsh-plugins#packages).

Почему автор выбрал REST и токен: в описанной им конфигурации MCP-сервер GitLab выключен для верхнеуровневой группы, пока Owner его не включит; выдаваемые этим сервером токены имеют область `mcp`, не подходящую для REST. Уже имеющийся подходящий персональный токен можно сохранить в хранилище учётных данных Harness под `dsh-gitlab/token`. Для чтения нужна область `read_api`, для описанных изменений — `api`. Фактическая доступность зависит от прав токена и настроек экземпляра GitLab.

## Возможности

- `gitlab_list_merge_requests`, `gitlab_get_merge_request`, `gitlab_get_job_log` и `gitlab_read` читают GitLab для агента. Список фильтруется по области, проекту, группе, строке поиска, меткам, автору или проверяющему. Инструмент отдельного запроса возвращает описание и метаданные, при необходимости diff, обсуждения и последнюю сборку с заданиями. Журнал задания — конец вывода неудачного задания. `gitlab_read` выполняет другие REST GET: задачи, коммиты, ветки, файлы репозитория, пользователи и поиск. Используется токен из Harness; агенту не нужно запускать `glab` или искать секрет на диске.
- `gitlab_present` показывает карточкой ожидающие твоей проверки запросы, твои запросы, результаты поиска, находки проверки конкретного запроса либо неудачные задания.
- Панель запроса на слияние содержит четыре раздела: **Обзор**, **Изменения**, **Обсуждения** и **Сборка**. Обсуждения фильтруются по незакрытым или находкам, поддерживают ответ и разрешение. В сборке показаны задания и по запросу журнал неудачного задания.
- `gitlab_review`: комментарий, ответ в ветке, разрешение или повторное открытие обсуждения, одобрение или его отзыв. Эти действия изменяют запрос на слияние; без `confirm` инструмент возвращает точный текст предполагаемой публикации. Панель показывает черновик с кнопкой отправки.
- Команды `/gitlab status|login|logout|sync`.

## Настройка

```yaml
- id: gitlab
  config:
    endpoint: https://gitlab.com
    debug: false
```

`endpoint` — корень экземпляра GitLab; вызовы выполняются под `/api/v4` этого адреса.
